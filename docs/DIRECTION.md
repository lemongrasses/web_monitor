# 方向(草稿,討論中)

先定方向,再整理功能,最後才改程式。這份文件記錄已經決定的和還沒決定的。功能清單與彼此的關係見 [FEATURES.md](FEATURES.md)。

最後更新:2026-11-17

## 1. 這個程式是什麼

**核心需求:監控。** 一個程式看著我們的軟體(AIO NAV 等)跑得怎麼樣,以及各個零件(IMU、GNSS、相機、網路、電腦本身)有沒有問題。這部分目前基本上都做到了。

**進一步的需求:找出原因,接著檢修。** 從監控看到的現象,追到原因,再在同一個地方處理。

**額外的需求(不是主軸):**
- 出貨機無人值守,自我檢查、全自動。
- 輸出給車輛(0x05 狀態封包)。這部分之後可能拔出來,在其他專案做成獨立功能。

## 2. 功能分層(草案)

依照上面的優先順序分層。下層不依賴上層:拿掉上層,下層照常運作。

| 層 | 目的 | 目前屬於這層的功能 |
|----|------|--------------------|
| **1. 監控**(核心) | 看到現在怎麼樣 | 0x04 接收解碼與 AIO NAV 狀態、系統 / 服務 / ROS / 網路、感測器燈號(IMU、GNSS、相機、LiDAR)、事件紀錄、系統紀錄器(sysmon)、GNSS 校時 |
| **2. 診斷** | 找出原因 | 診斷頁、GNSS / RTK 頁、即時預覽、ROS 主題、事件、sysmon 的 last-crash、紀錄檔下載、終端機 |
| **3. 檢修與設定** | 處理問題、調整 | 啟停 AIO NAV / drivers、AIO NAV 設定編輯器、槓桿臂、靜止偵測校正、Wi-Fi / 熱點、密碼 |
| **4. 自動運行**(選用) | 沒有人時自己處理 | 自動啟動、DSO / driver 監控、ROS 隔離檢查 |
| **5. 對車輛輸出**(選用,將來可能獨立) | 告訴車輛能不能用 | 0x05、給車輛的 10 種 readiness 狀態與 inhibit bits、「READY 需要 RTK」、vehicle gate、熱點封包複本 |
| **資料** | 收集與重播 | 資料下載、Bag 重播(目前閒置,方向待定) |

**目前和分層衝突的地方:**
- 健康評估(第 1 層)和給車輛的 readiness(第 5 層)交織在 `state/health.py` 裡。自動啟動(第 4 層)也讀 readiness。要把輸出拔出去,得先把這兩者分開。
- 「READY 需要 RTK」預設開,把第 5 層的規則套到整台機器上。但 RTK 其實要依環境決定(見第 3 節)。
- 使用者頁以「Ready / 對準進度」為主,是車輛操作員的視角。但出貨機平常沒人操作,第 1–3 層的使用者是工程師和第一次設定的人。

## 3. 已確定的事

**三種機器:**

| 機器 | 用途 | 操作的人 |
|------|------|----------|
| 出貨機 | 接車輛,無人值守,自我檢查、全自動 | 沒有人;出問題時工程師到現場 |
| 測試機 | 監控整機狀態、測試各種東西 | 工程師 |
| 開發機 | 遠端修問題時用來模擬的環境 | 工程師 |

**順序:** 先把所有功能整理好、修好,再依照情境決定每種機器要裝哪些選配。

**各功能當初的需求:**

| 功能 | 需求 | 結論 |
|------|------|------|
| 熱點 | 裝置大多在沒有網路的地方。第一次使用時,用手機或平板快速連進裝置做設定和操作 | 屬於「第一次設定」。沒有網路的環境本來就沒有 NTRIP,所以和 Wi-Fi 上網的衝突不是問題 |
| RTK | 不是一定要有,依環境決定。沒有 RTK 時,有些偵測和判斷要跟著改變 | 不應該預設強制。由環境設定決定 |
| 網路從哪來 | Wi-Fi 或網路線,依裝置而定 | 和熱點、RTK 相關,是環境設定的一部分 |
| 槓桿臂(Setup) | 讓使用的人依照自己的載具調整安裝位置,軟體才能正確運作 | 使用者自己的設定,保留在使用者頁 |
| Bag 重播 | 當初為了測試做的,目前閒置。方向應該是:收資料,之後可以重播 | 待定(有想法,另外整理) |
| 桌面 App(aio-nav-ui) | 已經沒有了 | 相容的部分可以移除;UDP 9000 不再有搶埠的問題 |
| 0x05 輸出 | 當初案子趕工,需要輸出給車輛 | 第 5 層,將來可能獨立 |

## 4. 討論中

- **測試機和開發機的分界。** 草案:用「資料從哪來」區分(測試機:真的感測器;開發機:Bag 重播或模擬)。
- **環境設定。** 草案:第一次設定時決定「網路從哪來、有沒有 RTK、有沒有接車輛」。之後各功能依照這些設定運作,不再各自猜。
- **使用者頁的對象。** 平常沒人操作時,使用者頁是給誰看的?第一次設定的人、到現場的工程師,還是車輛整合商?
- **給車輛的訊號。** 不是正常運行時,繼續送 MAINTENANCE 還是不送?需要和車輛端確認。
