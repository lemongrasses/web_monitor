# 方向(草稿,討論中)

先定方向,再整理功能,最後才改程式。這份文件記錄已經決定的和還沒決定的。功能清單與彼此的關係見 [FEATURES.md](FEATURES.md)。

最後更新:2026-11-17

## 1. 已確定

**出貨機的定位:** 裝在客戶的車上,讓車子能自動駕駛,**無人值守**。系統要盡量自我檢查、全自動運作。平常沒有人操作頁面,出問題時由工程師到現場處理。

**三種機器(用途):**

| 機器 | 用途 | 操作的人 |
|------|------|----------|
| 出貨機 | 接車輛,無人值守,自我檢查、全自動 | 沒有人;出問題時工程師到現場 |
| 測試機 | 監控整機狀態、測試各種東西 | 工程師 |
| 開發機 | 遠端修問題時用來模擬的環境 | 工程師 |

**順序:** 先把所有功能整理好、修好,再依照情境決定每種機器要裝哪些選配。

## 2. 討論中

- **測試機和開發機的分界。** 草案:用「資料從哪來」區分,不用「哪台電腦」區分。
  - 測試機:真的感測器。
  - 開發機:沒有感測器,用 Bag 重播或 Fake 模擬。
  - 也可以合成一種「工程機」,資料來源當成模式切換。
- **輸出給車輛不一定需要。** 有時只是收資料、做測試。「有沒有輸出給車輛」可能要是獨立的開關或模式。
  - 0x04 是 AIO NAV 自己送的(`output_udp`),0x05 是儀表板送的,兩者由不同的地方控制。
- **給車輛的訊號(0x05)。** 草案:0x05 是車輛唯一要看的安全訊號。不是正常運行時繼續送,但內容是 MAINTENANCE,不送 READY。
  - 這樣車輛能分辨「機器在維護」和「線斷了」。
  - 需要和車輛端(aio-nav-receiver)確認。
- **運作模式。** 草案:運行 / 維護 / 重播,一次只有一個,開機回到運行。要再加上「收資料、不輸出」的情況。
